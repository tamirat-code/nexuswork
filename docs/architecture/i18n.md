# Multi-Language & Internationalization (i18n) Architecture

## Overview

NexusWork supports multi-language capabilities using `i18next` and `react-i18next` on the frontend, with locale preference persistence on the user profile on the backend.

## Supported Locales

- `en` — English (Default)
- `am` — Amharic (አማርኛ)
- `af` — Afaan Oromoo

## Language Selection Priority

1. **User Account Preference**: Stored on `User.preferred_language` and returned via `/v1/auth/me`.
2. **Local Browser Persistence**: Saved in `localStorage` under key `nw_language`.
3. **Browser Navigator Language**: Detected via `i18next-browser-languagedetector`.
4. **Fallback**: English (`en`).

## Translation Resources Structure

Translation files are structured under `apps/frontend/src/i18n/`:

- `index.js` — Main i18next initialization and resource bundles.
- `locales/en.json` — English translation dictionary.
- `locales/am.json` — Amharic translation dictionary.
- `locales/af.json` — Afaan Oromoo translation dictionary.

## API & User Preference Endpoint

- `PATCH /v1/users/me/preferences`
  - Body: `{ preferred_language: "en" | "am" | "af" }`
  - Persists preference in MongoDB and updates local state.
